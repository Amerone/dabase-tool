## 3. 发现的问题（按严重度）

## P1-1：缺少“任务优先级与关键路径”标注

风险：

1. 团队并行开发时可能先做非关键项，导致里程碑延误。

修订建议：

1. 给每个任务补充 `priority`（P0/P1/P2）。
2. 标注关键路径：
- A-1 -> A-2 -> A-3 -> C-1 -> C-3

## P1-2：缺少明确的人天估算区间

风险：

1. 8-10 周节奏可能与实际资源不匹配。

修订建议：

1. 给每个任务包增加估算：
- 小（1-2d）
- 中（3-5d）
- 大（6-10d）

## P1-3：缺少“冻结窗口”定义

风险：

1. 在 C/D 阶段继续变更 API 契约可能引发返工。

修订建议：

1. 定义冻结点：
- Phase A 结束冻结 trait 草案 v1
- Phase C 结束冻结 `CapabilityReport` v1

## P2-1：summary.json 字段尚未给出样例

风险：

1. 前后端/运维对接时解释不一致。

修订建议：

1. 追加 JSON 样例并纳入契约测试。

## P2-2：Kingbase/Shentong 纳入矩阵节奏未细化

风险：

1. 可能长期停留在“计划支持”，缺少落地时间点。

修订建议：

1. 在 Phase D 增加 D-3 子任务：
- 先接入 metadata 最小集
- 再逐项补齐对象能力
